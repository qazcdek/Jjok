# ADR-0003: 사용자 데이터는 users/{uid} 아래, 필터·그래프 계산은 클라이언트에서

- 상태: accepted (2026-10-19 승인)
- 날짜: 2026-10-19
- 근거: DEV-003 §1

## 배경

Firestore는 쿼리당 array-contains 하나만 허용해 축 교차 필터를 쿼리로 풀기 어렵다. 보안 규칙도 단순해야 한다.

## 결정

- 모든 사용자 데이터는 `users/{uid}/...` 하위 컬렉션에 둔다.
- Work 목록 전체를 구독해 클라이언트 메모리에서 필터·교차·엣지 계산을 한다.
- 공용 데이터는 `citationCache`만 최상위에 둔다.

## 결과

- 규칙이 '본인 경로만'으로 단순해진다. 계정 삭제가 쉽다.
- 라이브러리가 수만 편이 되면 첫 로딩이 느려진다 → v1 대상 규모(수천 편 이하)에서는 문제없다고 가정, M7 성능 점검에서 확인.
