# 요구사항 목록 및 추적표

기능 명세의 항목에 고정 ID를 붙여, 작업·테스트·커밋에서 같은 ID로 참조한다.
ID 형식: `F-<영역>.<항목>[.<세부>]` (기능), `N-<번호>` (비기능). 영역 번호는 기능 명세의 절 번호와 같다.

## 2. 비기능 요구사항

| ID | 요구사항 | 검증 | 마일스톤 |
| --- | --- | --- | --- |
| N-01 | 사용자는 자기 데이터만 읽고 쓸 수 있다 | 보안 규칙 테스트 (08 문서) | M0 |
| N-02 | API 키 평문은 브라우저로 내려가지 않고, 로그에도 남지 않는다 | 서버 테스트 + 코드 리뷰 | M6/M7 |
| N-03 | 메타데이터 자동 채움 성공률 ≥ 90% (50편 기준) | 평가 데이터셋 | M1 |
| N-04 | 앱은 LLM 비용을 부담하지 않는다 (사용자 키만 사용) | 설계 검토 | M6 |
| N-05 | Firestore 무료 한도 안에서 베타 운영 (사용자 5~10명) | 사용량 대시보드 점검 | M4, M7 |
| N-06 | llama server 옵션은 `APP_ENV=dev`일 때만 노출 | 서버·클라이언트 테스트 | M6 |
| N-07 | 오프라인 상태에서 라이브러리·노트 열람 가능 (Firestore 오프라인 캐시) | 수동 테스트 | M1/M3 |

## 3. 범위 밖 (v1에서 만들지 않음)

플러그인·확장 API, 브라우저 커넥터, 웹 스냅샷, EPUB, 그룹 라이브러리, 리더 디자인 테마, 원문 전문 검색, 워드프로세서 플러그인, CSL 전체 스타일, 임베딩 검색(v1.1).
