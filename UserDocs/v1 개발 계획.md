Oct 19, 2026 · @qazcde

앞의 네 마일스톤(M0–M3)이 끝나는 1월 10일에 "읽고 기록하는" 최소 제품이 완성되고, 그 뒤로 그래프와 AI가 차례로 붙는다.

## 마일스톤별 범위와 완료 기준

순서는 "데이터가 들어온다 → 읽는다 → 기록한다 → 연결해 본다 → AI가 돕는다" 흐름을 따른다. 각 마일스톤은 완료 기준을 통과해야 다음으로 넘어간다.

| 마일스톤 | 기간 | 주요 작업 | 완료 기준 |
| --- | --- | --- | --- |
| M0 기반 | 2주 (10/26–11/8) | 저장소·CI 구성, Firebase 프로젝트(dev/prod), 구글 로그인 + `drive.file` 권한, Firestore 스키마 v0와 보안 규칙, `APP_ENV` 플래그, OAuth 동의 화면 검증 신청 | 로그인 후 드라이브에 파일을 올리고 다시 받을 수 있다. 다른 계정의 문서는 읽을 수 없다 |
| M1 라이브러리 코어 | 3주 (11/9–11/29) | PDF 업로드 → 드라이브 저장, DOI·arXiv ID 추출과 메타데이터 조회, 식별자로 추가, 논문/버전 데이터 모델, 다차원 컬렉션 축, 태그, 목록·필터 UI | 논문 50편을 올려 메타데이터가 90% 이상 자동으로 채워지고, 축 교차 필터가 동작한다 |
| M2 리더·주석 | 3주 (11/30–12/20) | pdf.js 리더(포맷 어댑터 구조), 하이라이트·영역 주석, 포맷 독립 앵커 모델, 링크 엔티티와 백링크, 다크 모드 | 하이라이트를 다른 논문의 하이라이트에 링크하고, 양쪽에서 백링크로 이동할 수 있다 |
| M3 노트 | 3주 (12/21–1/10) | Markdown 에디터, 위키 링크·백링크, 노트–논문 다대다 연결, 사용자 템플릿 관리, 노트 그래프 v0 | 템플릿으로 노트를 만들고, 위키 링크로 엮은 노트 그래프를 볼 수 있다 |
| M4 계보 그래프 | 3주 (1/11–1/31) | Semantic Scholar/OpenAlex 인용 자동 수집, 주기 업데이트 작업, 엣지 기준 선택, 그래프 뷰 저장, 활성 노드 내비게이션(탭 대체) | 같은 컬렉션을 인용 기준과 공동 저자 기준 두 그래프로 전환하고, 활성 노드로 리더를 오간다 |
| M5 에이전트 기반·소스 검색 | 3주 (2/1–2/21) | FastAPI + LangGraph 에이전트 서버, uv tool 계약·레지스트리, 검색 도구(arXiv, OpenReview, DBLP, S2), 버전·venue 매칭 도구, 중복 병합 UI | 앱에서 소스별 검색 결과를 바로 추가하고, arXiv 버전과 학회 버전이 한 논문으로 묶인다 |
| M6 AI 기능 | 3주 (2/22–3/14) | BYOK 키 암호화 저장, LLM 라우팅(Gemini/OpenAI/Claude, dev 전용 llama server), 요약·주석 제안·Q&A, AI 문서를 노트로 저장, 파생 문서 검색 | 사용자 키로 요약을 만들면 노트로 저장되고 검색에 걸린다. dev에서 llama server로 같은 흐름이 동작한다 |
| M7 인용·출시 준비 | 2주 (3/15–3/28) | 인용 스타일 4종(APA, IEEE, ACM, Chicago) + BibTeX, 빠른 복사, 보안 점검(키 보관, 보안 규칙), 성능 점검, 프로덕션 배포 | 비공개 베타 사용자 5명 이상이 실제 라이브러리를 옮겨 1주일 사용한다 |

베타 공개 목표일은 2027년 3월 29일이다. M2·M3·M4는 M1의 데이터 모델만 공유하므로, 개발자가 둘이면 병렬로 진행해 전체를 약 3주 줄일 수 있다.

## 기술 스택 제안

구글 생태계(Firebase, Cloud Run)로 통일해 인증·배포·비밀 관리를 한곳에서 처리한다. M0에서 확정한다.

| 영역 | 제안 | 이유 |
| --- | --- | --- |
| 웹 프론트엔드 | React + TypeScript + Vite (SPA) | 리더·그래프·에디터 위주의 클라이언트 앱이라 SSR이 필요 없다 |
| 호스팅 | Firebase Hosting | 인증·DB와 같은 프로젝트에서 배포 |
| 인증 | Firebase Authentication (구글) | 구글 로그인 한 번으로 드라이브 권한까지 요청 |
| DB | Firestore | 무료 플랜, 실시간 동기화, 오프라인 캐시 |
| PDF 리더 | pdf.js | 사실상 표준, 텍스트 레이어로 앵커 구현 가능 |
| Markdown 에디터 | CodeMirror 6 | 위키 링크 자동완성·커스텀 문법 확장이 쉽다 |
| 그래프 | Cytoscape.js | 엣지 기준별 스타일·레이아웃 전환 |
| 파생 문서 검색 | 브라우저 측 키워드 인덱스(예: MiniSearch) | 웹 앱이므로 명세의 SQLite FTS5 대신. 임베딩 검색은 v1.1 |
| 에이전트 서버 | FastAPI + LangGraph, Cloud Run | Python 단일 스택, 사용량 기반 과금 |
| 에이전트 도구 | uv tool 패키지 (stdin/stdout JSON 계약) | 도구별 격리 환경 |
| 주기 작업 | Cloud Scheduler + Cloud Run job | 인용 관계 자동 업데이트 |
| 키 암호화 | Cloud KMS | BYOK 키 암호화의 암호화 키 보관 |

## 리스크와 대응

일정에 가장 큰 영향을 줄 수 있는 것은 구글 OAuth 앱 검증과 PDF 메타데이터 추출 정확도다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 구글 OAuth 동의 화면 검증 지연 | 프로덕션 출시 지연 | M0에서 바로 신청. 검증 전에는 테스트 사용자(최대 100명)로 베타 운영 |
| PDF 메타데이터 추출 실패율 | M1 완료 기준 미달 | 식별자 추출 실패 시 제목으로 S2/OpenAlex 검색, 그래도 실패하면 사용자 확인 UI |
| 외부 API 속도 제한(S2, OpenAlex) | 인용 수집·자동 업데이트 지연 | S2 API 키 신청, 결과 캐시, 주기 작업에서 일괄 처리 |
| Firestore 무료 한도 초과 | 비용 발생 | 그래프·인용 데이터는 문서 단위를 크게 묶어 읽기 횟수 절감, M4 이후 사용량 점검 |
| 포맷 독립 앵커 설계 실수 | Markdown 지원 시 주석 재작업 | M2 시작 전에 Markdown 문서로도 앵커를 시험하는 스파이크(2일) |
| 1인 개발 일정 초과 | 베타 지연 | 각 마일스톤 완료 기준을 고정하고, 넘치는 작업은 v1.1 목록으로 이동 |
